Phase 2

Subscription System & Real-World Challenges

New Features Implemented

1. Nested Data Structures

Evolved from single struct to nested architecture:

Before:
struct stMember {
    string MemberId;
    string Name;
    string Phone;
    int Age;
};
→
After:
struct stSubscription {
    string SubscriptionType;
    string StartDate;
    string EndDate;
    bool IsActive;
    double SubscriptionPrice;
};

struct stMember {
    string MemberId;
    string Name;
    string Phone;
    int Age;
    stSubscription Subscription;
};

Why this matters: Separating concerns allows better organization and makes the code more maintainable and scalable.

2. Enum-Based Subscription Types

Implemented type-safe subscription management:

enum enSubscriptionType {
    Monthly = 1,      // $50
    Quarterly = 2,    // $120
    SemiAnnual = 3,   // $200
    Annual = 4        // $350
};

Benefit: Type safety prevents invalid subscription types and enables automatic pricing.

3. Automatic Date Calculation

Built functions to automatically calculate subscription end dates:

string CalculateEndDate(enSubscriptionType Type) {
    time_t now = time(0);
    tm* ltm = localtime(&now);
    
    switch (Type) {
        case Monthly:    ltm->tm_mon += 1; break;
        case Quarterly:  ltm->tm_mon += 3; break;
        case SemiAnnual: ltm->tm_mon += 6; break;
        case Annual:     ltm->tm_year += 1; break;
    }
    
    mktime(ltm);
    // Format and return date string
}

Impact: Eliminates manual date entry errors and ensures consistency.

4. Separated Display Tables

Improved UX by separating members with and without subscriptions:

  • Table 1: Members WITH subscriptions (shows subscription details)
  • Table 2: Members WITHOUT subscriptions (shows basic info)

User Experience: Clear visual distinction makes data easier to scan and understand.

Challenges & Problems Encountered

Real problems faced during development and how they were systematically solved:

Challenge #1

Infinite Loop in Display

Critical
Problem:

The program would print the same line repeatedly, freezing the terminal.

# Output kept repeating:
Member ID: M002 | Sara Mohammad | Monthly | 12-04-2025 | Active
Member ID: M002 | Sara Mohammad | Monthly | 12-04-2025 | Active
Member ID: M002 | Sara Mohammad | Monthly | 12-04-2025 | Active
# ... forever
Root Cause:

Missing break statements in the switch-case menu handler:

// BUGGY CODE:
void PerformMenuChoice(int choice) {
    switch (choice) {
        case 1:
            PrintAllMembersData(vMembers);
            // ❌ Missing break! Falls through to case 2
        case 2:
            AddNewMember();
            // ❌ Missing break! Falls through to case 3
        // ...
    }
}
Solution:

Added break statements to prevent fall-through:

// FIXED CODE:
void PerformMenuChoice(int choice) {
    switch (choice) {
        case 1:
            PrintAllMembersData(vMembers);
            break;  // ✅ Prevents fall-through
        case 2:
            AddNewMember();
            break;  // ✅ Exits switch properly
        // ...
    }
}
Lesson Learned:

Always include break statements in switch cases unless intentional fall-through is desired. This is a common C++ pitfall.

Challenge #2

File Corruption with Repeated Lines

Critical
Problem:

The Members.txt file contained hundreds of duplicate corrupted lines:

M150#//#Walaa Ibrahim#//#929-000-0000#//#39
M151#//#Latifah Mohammad#//#719-0000-99999#//#33
#//##//##//#0#//#Quarterly#//#11-04-2025#//#02-04-2026#//#1#//#120.000000
#//##//##//#0#//#Quarterly#//#11-04-2025#//#02-04-2026#//#1#//#120.000000
#//##//##//#0#//#Quarterly#//#11-04-2025#//#02-04-2026#//#1#//#120.000000
# ... repeated 300+ times!
Root Cause:

Bug in the UpDateClientByMemberID function - subscription data was lost during update:

// BUGGY CODE:
stMember ChangeMemberRecod(string MemberID) {
    stMember Member;
    Member.MemberId = MemberID;
    
    // Read new name, phone, age...
    // ❌ Problem: Returns member WITHOUT subscription data!
    
    return Member;  // Subscription is empty!
}

This created members with empty IDs and default subscription data, which kept getting written to file.

Solution:

Step 1: Clean the corrupted file manually

# Remove corrupted lines, keep only valid members
nano Members.txt

Step 2: Fix the update function to preserve subscription data:

// FIXED CODE:
bool UpDateClientByMemberID(string MemberID, vector<stMember> &vMembers) {
    // Find member...
    
    for (stMember &M : vMembers) {
        if (M.MemberId == MemberID) {
            // ✅ Save subscription data before update
            stSubscription oldSubscription = M.Subscription;
            
            // Update basic info
            cout << "Enter Member Name? ";
            getline(cin >> ws, M.Name);
            // ... update other fields
            
            // ✅ Restore subscription data
            M.Subscription = oldSubscription;
            break;
        }
    }
}
Lesson Learned:

When updating records, preserve data that shouldn't change. Always test file operations with actual data to catch corruption early.

Challenge #3

Infinite Loop from Empty Input

High
Problem:

Pressing Enter without typing a Member ID caused infinite error messages:

Please enter MemberID ? [Enter pressed]
Member with [] already exists!
Enter another Member ID ? 
Member with [] already exists!
Enter another Member ID ? 
# ... repeated forever
Root Cause:

No validation for empty input, and the file had an empty line that matched "":

// BUGGY CODE:
string ReadMemberID() {
    string MemberID = "";
    cout << "Please enter MemberID ? ";
    cin >> MemberID;  // ❌ If user presses Enter, MemberID stays ""
    return MemberID;  // ❌ Returns empty string!
}
Solution:

Added empty input validation with loop:

// FIXED CODE:
string ReadMemberID() {
    string MemberID = "";
    
    do {
        cout << "Please enter MemberID ? ";
        cin >> ws;
        getline(cin, MemberID);
        
        if (MemberID.empty()) {
            cout << "❌ Member ID cannot be empty!\n";
            continue;
        }
        
        break;
    } while (true);
    
    return MemberID;
}
Lesson Learned:

Never trust user input. Always validate for empty strings, especially when they're used as search keys.

Challenge #4

Arabic Numerals Causing Input Failure

Medium
Problem:

Accidentally typing Arabic numbers (١٢٣) instead of English (123) froze the menu:

Choose option [1-6]? ٥  # Arabic 5
# Program freezes, keeps asking for input forever
Root Cause:

cin >> Choice fails when it can't parse the input as an integer, leaving cin in a failed state:

// BUGGY CODE:
int ReadMenuChoice() {
    int Choice = 0;
    cout << "Choose option [1-6]? ";
    cin >> Choice;  // ❌ Fails on non-integer input
    return Choice;  // ❌ Returns 0, menu repeats
}
Solution:

Added input failure handling with error state clearing:

// FIXED CODE:
int ReadMenuChoice() {
    int Choice = 0;
    cout << "Choose option [1-6]? ";
    
    while (!(cin >> Choice)) {
        cin.clear();  // ✅ Clear error state
        cin.ignore(numeric_limits<streamsize>::max(), '\n');  // ✅ Discard bad input
        cout << "❌ Invalid input! Please enter a number [1-6]: ";
    }
    
    return Choice;
}
Lesson Learned:

Always handle cin failures. Users can type anything, and the program must gracefully recover from invalid input.

Challenge #5

Unvalidated Member ID Format

Medium
Problem:

Users could enter any string as Member ID, causing confusion:

Enter Member ID ? Faris Ayesh  # ❌ Accepted!
Enter Member ID ? 12345        # ❌ Accepted!
Enter Member ID ? ABC###       # ❌ Accepted!

This made data inconsistent and searching difficult.

Analysis:

No format validation existed. The system needed a standard format for professionalism and consistency.

Solution:

Step 1: Define required format: M + digits (e.g., M001, M150)

Step 2: Create validation function:

bool IsValidMemberID(string MemberID) {
    // Must be at least 2 characters (M + digit)
    if (MemberID.length() < 2) {
        return false;
    }
    
    // Must start with 'M' or 'm'
    if (MemberID[0] != 'M' && MemberID[0] != 'm') {
        return false;
    }
    
    // Rest must be digits only
    for (int i = 1; i < MemberID.length(); i++) {
        if (!isdigit(MemberID[i])) {
            return false;
        }
    }
    
    return true;
}

Step 3: Apply validation in input functions:

string ReadMemberID() {
    string MemberID = "";
    
    do {
        cout << "Enter MemberID (Format: M + numbers) ? ";
        cin >> ws;
        getline(cin, MemberID);
        
        if (MemberID.empty()) {
            cout << "❌ Member ID cannot be empty!\n";
            continue;
        }
        
        if (!IsValidMemberID(MemberID)) {
            cout << "❌ Invalid format! Must start with 'M' + numbers.\n";
            cout << "   Examples: M001, M150, M9999\n";
            continue;
        }
        
        break;
    } while (true);
    
    return MemberID;
}
Lesson Learned:

Defining and enforcing data formats early prevents inconsistency and makes the system more professional and maintainable.

Challenge #6

Subscription Data Lost During Member Update

High
Problem:

When updating a member's basic info (name, phone), their subscription data disappeared:

# Before update:
Member: M002 | Sara Mohammad | Monthly | Active

# After updating name:
Member: M002 | Sara Ahmed | [No subscription data]
Root Cause:

The ChangeMemberRecod function created a new member object without copying subscription data:

// BUGGY APPROACH:
stMember ChangeMemberRecod(string MemberID) {
    stMember Member;  // ❌ New empty member
    Member.MemberId = MemberID;
    
    // Read new name, phone, age
    // Subscription remains empty!
    
    return Member;  // ❌ Returns member without subscription
}
Solution:

Modified update logic to preserve subscription data:

bool UpDateClientByMemberID(string MemberID, vector<stMember> &vMembers) {
    // ... find member ...
    
    for (stMember &M : vMembers) {
        if (M.MemberId == MemberID) {
            // ✅ Save subscription before modifying
            stSubscription oldSubscription = M.Subscription;
            
            // Update only basic info
            cout << "Enter Member Name? ";
            getline(cin >> ws, M.Name);
            
            cout << "Enter Phone? ";
            getline(cin, M.Phone);
            
            cout << "Enter Age? ";
            cin >> M.Age;
            cin.ignore();
            
            // ✅ Restore subscription data
            M.Subscription = oldSubscription;
            
            break;
        }
    }
    
    // Save to file...
}
Lesson Learned:

When updating records with nested structures, carefully preserve data that shouldn't change. Consider what fields should be editable vs. immutable.

Architecture Evolution

  • Mixed display (all members in one table)
  • Manual pricing entry
  • No date automation
  • Basic file operations

Final Architecture

  • Nested structs (Member + Subscription)

Key Lessons Learned

Never Trust User Input

Every input point needs validation. Users can and will enter unexpected data - the system must handle it gracefully.

Test with Real Data

Many bugs only appear with actual file operations and real user scenarios. Don't just test happy paths.

Structure Matters

Good data structure design (like nested structs) makes features easier to implement and less prone to bugs.

Handle cin Failures

Input streams can fail. Always check and clear error states, especially when reading numbers.

Preserve Data Carefully

When updating records, be explicit about what changes and what doesn't. Data loss is often silent and dangerous.

Enforce Standards Early

Defining data formats (like Member ID structure) prevents inconsistency and makes the system more professional.
